### THE 7-STAGE SYSTEM PIPELINE
Implement a deterministic pipeline with these sequential stages:
1. Upload & Store: Receive files (PDF, PNG, JPG, DOCX), generate an immutable document ID, validate constraints, and store the file.
2. Parse & Understand: Use IBM Docling to convert the document into structured Markdown + layout metadata. Compute a Page Quality Score. Fall back to OCR if scanned/low-quality.
3. Structured Field Extraction: Pass Docling Markdown output to Granite 3.0 via IBM watsonx.ai using structured outputs (Pydantic schema). Extract fields: `currency`, `due_date`, `invoice_date`, `invoice_number`, `subtotal`, `tax_amount`, `total_amount`, `vendor_name`, along with per-field confidence scores (0.00–1.00).
4. Mathematical & Deterministic Rule Engine:
   - Execute exact arithmetic validation: `expected_total = subtotal + tax_amount`.
   - If `subtotal + tax_amount != total_amount`, set `is_math_valid = False`.
   - Penalty logic: If math fails, automatically drop individual confidence scores for `subtotal`, `tax_amount`, and `total_amount` to forced low values (e.g., 50%), flag a clear error message: "Invoice Math: Subtotal (X) + Tax (Y) = Z, which does not match stated Total (W)".
5. Confidence-Based Routing Engine:
   - `AUTO_APPROVED`: Overall Confidence >= 90% AND `is_math_valid == True`. Instantly posted to PostgreSQL without human touch.
   - `NEEDS_REVIEW`: Overall Confidence 70%–89% AND `is_math_valid == True`. Sent to review queue with low-confidence fields highlighted in yellow.
   - `ACTION_REQUIRED`: Overall Confidence < 70% OR `is_math_valid == False`. Mandatory human verification required. Failing fields highlighted in red.
6. Persistent Storage (PostgreSQL): Save all normalized document entities, extracted key-value pairs, validation status flags, and user edits.
7. Immutable Audit Trail: Log every system transition, score calculation, rule flag, and human override with precise timestamps.
